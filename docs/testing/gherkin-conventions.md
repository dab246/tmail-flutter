# Gherkin non-regression scenarios: conventions

Rules for `integration_test/features/**/*.feature`. They are enforced by `ScenarioMetadata` (`integration_test/gherkin/scenario_metadata.dart`) at run time and by `test/integration_test/gherkin/feature_files_test.dart` in the unit-test job. How to run and add scenarios: [gherkin-runbook.md](gherkin-runbook.md). Background and design: [gherkin-assessment.md](gherkin-assessment.md).

## Layout

```
integration_test/features/
  <area>/<topic>.feature        one file per feature, directly under its area (composer, search, …)
  <area>/<topic>_test.dart      generated by build_runner, gitignored, never edited
  steps/<step_text>.dart        one step definition per file, shared by every feature
```

Feature files must sit exactly one level below `features/`: generated tests and step files share one relative import (`bdd_options.yaml`). Never name a hand-written file `*_test.dart` anywhere under `integration_test/`: Patrol bundles every such file as a test, and one without `main()` breaks the compilation of the whole e2e suite (the unit-test guard checks this).

## Writing a scenario

```gherkin
Feature: Composer editor keyboard shortcuts
  The rich-text editor maps shortcuts to Twake Mail's own dialogs
  instead of the embedded editor's native ones.

  @NR-COMPOSER-001 @P2 @web @src:issue-4488 @src:pr-4539
  Scenario: the insert link shortcut opens the custom link dialog
    Given bob has opened a new composer
    When bob presses the insert link shortcut in the editor
    Then the custom insert link dialog is shown
```

- One scenario checks one behaviour or business rule.
- The title states the expected behaviour, not the implementation.
- `Given` builds the starting state reproducibly (provisioning through robots or `CommonRobot`, never leftovers of another scenario).
- `When` is one action that matters to the user.
- `Then` asserts the outcome through an `expect*` robot method. A `Then` that only repeats that an action happened is not an assertion.
- `bob` is the signed-in user (`BASIC_AUTH_EMAIL`) and `alice` the other provisioned user (`ADDITIONAL_MAIL_RECIPIENT`).
- Values go in braces so they become step parameters: `Given bob has a draft {'Weekly report'}`. Quoted text without braces becomes part of the step name.
- Supported: `Background`, `Rule`, `Scenario Outline` + `Examples`, data tables. Not allowed: raw Dart lines above `Feature:` and `After:` sections (non-standard `bdd_widget_test` extensions the guard cannot parse).
- Keep step text ASCII letters, digits and spaces. Punctuation is dropped from the step name, so `insert-link` and `insertlink` would name the same step.

## Tags

Tags go on `Scenario`, `Scenario Outline` or `Rule` (inherited by its scenarios), **never on `Feature:`**: Patrol bundles test files and does not apply library-level tags, so feature tags could never be selected.

| Tag | Required | Rule |
|---|---|---|
| `@NR-<AREA>-<NNN>` | exactly one | Unique across all features, never reused after a scenario is deleted. `<AREA>` upper-case letters/digits (`COMPOSER`, `SEARCH`), `<NNN>` three digits. Every row of an outline shares the outline's id. |
| `@P1` / `@P2` / `@P3` | exactly one | P1: a regression blocks a release (sending, receiving, reading mail, login). P2: a main feature is broken but has a workaround. P3: minor or cosmetic. |
| `@android` / `@ios` / `@web` | at least one | Only platforms on which the scenario has been run green. CI runs `@web` on every PR and `@android` nightly. |
| `@smoke` | optional | Small subset for quick checks. |
| `@src:pr-<n>` / `@src:issue-<n>` | optional, repeatable | The `linagora/tmail-flutter` PR or issue the scenario guards against. It must exist and be about this behaviour. |
| `@verified:YYYY-MM-DD` | optional, at most one | The date someone checked that the expected outcome matches the product (spec, issue or manual check), not only that the test ran green. Not in the future. Update it only after re-verifying. |

Any other tag fails the run. To add a new optional group, add it to `ScenarioMetadata.groupTags` and to this table.

`key:value` tags (`src`, `verified`) are traceability only: `test_api` rejects `:` in tag names, so they are never passed to Patrol and cannot be used with `--tags`. Everything else, plus the implicit `gherkin` tag added to every scenario, can be used with `--tags`.

Reports show the id in front of the title: `NR-COMPOSER-001 the insert link shortcut opens the custom link dialog`.

## Steps

- A step is a top-level function `Future<void> stepName(PatrolIntegrationTester $, …)` in `features/steps/<step_name>.dart`, named by the generator from the step text. Reusing the exact text reuses the function.
- A step with no definition is generated as a stub that throws `UnimplementedError`: the scenario fails, and the unit-test guard fails until the stub is implemented.
- Steps call robots from `FeatureWorld.current.robots` (the same `RobotFactory` the classic scenarios use) and follow the existing robot pattern: no raw `$()` finders in steps; when a step needs a new action or assertion, add it to the robot (`integration_test/robots/abstract/` + mobile + `web/` implementations).
- Steps do not keep state in globals. If a later step needs data from an earlier one, add a field to `FeatureWorld` (it is reset after every scenario).
